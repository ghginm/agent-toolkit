## Project map

- If `.agent/project-map/index.md` exists, consult it before significant exploration; follow its routing to relevant cards and source files.
- Treat cards as navigation aids, not authority. Before implementation, verify the actual code, tests, and relevant dependencies, callers, and interfaces even when cards look fresh.
- When useful facts change (responsibilities, interfaces, entrypoints, contracts, or dependencies), update only the affected cards.
- If the map or other documentation is missing, insufficient, or wrong, fall back to source inspection and direct repository search; code wins. Repair or flag misleading cards when authorized.
